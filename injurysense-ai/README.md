# InjurySense AI

**Detect. Analyze. Prevent. Perform Safer.**

InjurySense AI is a browser-first sports-safety screening platform. The live modules use real browser/device capabilities when available:

- Real webcam via `getUserMedia()`
- MediaPipe Pose Landmarker for live body landmarks
- MediaPipe Face Landmarker for face/eye landmarks
- Web Audio API for microphone signal analysis
- Speech Recognition for voice commands where supported
- Speech Synthesis for AI Coach voice output
- Device Motion / Orientation where supported and permitted
- Camera-derived motion fallback when sensors are unavailable
- Server-side AI Coach integration through an OpenAI-compatible HTTP endpoint when configured
- MongoDB-backed session history when MongoDB is available

## Important safety note

This is an AI-assisted screening and sports-safety tool. It does **not** diagnose ACL tears, concussion, neurological disease, eye disease, or other medical conditions. Live results are observations/indicators and should not replace professional assessment.

## Open the frontend offline

The workspace-root `index.html` is generated by the client production build. From the `injurysense-ai` project directory, run `npm run build` once after source changes, then open the workspace-root `index.html` directly in Chrome, Edge, Firefox or Brave. The generated file embeds the frontend JavaScript and CSS; displaying it and navigating its pages does not require Node.js, localhost, internet access, or the backend.

The status banner identifies offline mode. Account, saved-report and cloud-coach actions require the backend. Live camera and microphone access depends on browser permissions and file-origin policy. Pose and eye landmark analysis require MediaPipe model assets from the internet and are explicitly unavailable in offline file mode; no simulated measurements are shown as real results. Use localhost or HTTPS for browser APIs that reject file origins.

## 2. Environment

Copy `.env.example` to `.env`.

Required for normal development:

```env
PORT=5000
MONGODB_URI=mongodb://127.0.0.1:27017/injurysense_ai
JWT_SECRET=change-this-in-production
```

Optional real AI Coach provider:

```env
AI_API_URL=https://your-openai-compatible-endpoint/v1/chat/completions
AI_API_KEY=your-server-side-key
AI_MODEL=your-model-name
```

Never put `AI_API_KEY` in React/client code.

## Browser permissions

### Camera

Use Chrome/Edge/Safari on `localhost` or HTTPS. Click **Start camera** and choose **Allow** when prompted.

If access was denied, open the browser site permissions for the application and allow Camera, then retry.

### Microphone

Open Voice Analysis or AI Coach and click the microphone button. Allow microphone access. Web Audio analysis continues independently of Speech Recognition when Speech Recognition is unsupported.

### Motion sensors

On browsers that require an explicit permission request, start Motion Analysis and approve motion access. If motion sensors are unavailable or blocked, the page uses camera-derived movement instead and labels the mode accordingly.

## How to test the real modules

### Live Camera

1. Open **Live Camera**.
2. Click **Start camera**.
3. Allow camera permission.
4. Wait for **Pose AI: ACTIVE** / processing to finish.
5. Move your shoulders, elbows, hips and knees.
6. The skeleton overlay and joint measurements should change with movement.
7. Choose **Save session** to persist a summary when MongoDB is connected.

If the pose model cannot load, the page shows the error rather than pretending that pose detection is active.

### Motion Analysis

1. Open **Motion Analysis**.
2. Click **Start analysis**.
3. Approve motion permissions if requested.
4. Move the device/body in front of the camera.
5. Observe real velocity, acceleration, motion intensity and relative momentum samples.
6. Sudden movement spikes are added to the impact timeline only when the measured signal crosses the detection rule.
7. Use **Pause**, **Reset** and **Save session**.

`Relative momentum` is deliberately an index. It is not physical momentum because body mass and calibrated units are not available.

### Voice Analysis

1. Open **Voice Analysis**.
2. Click **Start listening**.
3. Allow microphone access.
4. Speak normally.
5. Watch the live waveform, audio level, RMS-like signal energy and zero-crossing count.
6. Final speech appears in the transcript when Speech Recognition is supported.
7. Try commands such as `start camera`, `start motion analysis`, `open eye analysis`, `start AI coach`, or `emergency`.

### Eye Analysis

1. Open **Eye Analysis**.
2. Read the privacy notice.
3. Click **Start eye analysis**.
4. Allow camera permission.
5. Wait for Face AI to become active.
6. Blink and move your gaze.
7. Watch blink count/rate, approximate eye openness and coarse gaze direction.
8. Click **Stop camera** to release the camera.

Eye metrics are approximate visual-attention indicators, not medical measurements.

### AI Coach

1. Open **AI Coach**.
2. Type a question or press the microphone button.
3. If Speech Recognition is available, speak naturally.
4. The text is sent to `/api/coach/chat`.
5. If `AI_API_KEY`, `AI_API_URL` and `AI_MODEL` are configured, the backend calls the configured server-side AI provider.
6. Without those settings, the response is clearly marked **AI DEMO MODE**.
7. Press **Speak** to use browser Text-to-Speech.

## Demo mode rules

Demo mode is used only for unavailable server-side AI or unavailable browser/device/model capabilities. Live camera, microphone, pose, face and sensor values are never filled with random numbers.

The UI uses explicit states such as:

```text
READY
ACTIVE
PROCESSING
PERMISSION REQUIRED
UNSUPPORTED
ERROR
DEMO MODE
```

## Privacy

Camera and microphone streams are stopped when their module is stopped/unmounted. Camera/audio/video content is not uploaded by the live modules. Saved sessions contain summary metrics only unless you explicitly extend the application to store media.

## Troubleshooting

- If the camera is black, verify site camera permission and close other applications using the camera.
- If microphone input is flat, verify the microphone permission and selected OS input device.
- If Speech Recognition is unsupported, voice activity analysis still works, but browser speech-to-text commands may not.
- If MediaPipe cannot load, check internet access because the task model is downloaded by the browser from the configured model/CDN URLs.
- If MongoDB is offline, live browser features still work; saved-session persistence is unavailable.
- Use `localhost` or HTTPS for camera/microphone access.
